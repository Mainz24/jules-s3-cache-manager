# Изначальная задача

> Записано 2026-10-24. Текст задачи не редактируется — он эталон, с которым
> сверяется готовый результат. Всё, что сказано позже, дописывается

Начинаем разработку модуля с делегированием кодинга внешнему воркеру Google Jules (Zero Footprint) и боевым E2E-тестированием в нашем кластере.

Твоя роль — оркестратор по регламенту Autopilot (Manual mode).

Ход выполнения задачи:
1. Создай через gh CLI тестовый репозиторий: `Mainz24/jules-s3-cache-manager` (Python 3.11+ / README).
2. Сформируй манифест и первичный бриф задачи.
   Суть задачи: Написать асинхронный клиент кэширования для S3-совместимого хранилища (aiobotocore / boto3 + Pydantic v2). 
3. Передай бриф субагенту-планировщику (planner через agent-runner).
   Требование к плану для Jules (Two-Tier Testing):
   - Tier 1 (Unit для Jules): Контрактные тесты на моках/фикстурах в `tests/unit/`, которые Jules обязан успешно прогнать в Google Sandbox командой `pytest tests/unit/ -v` перед открытием PR.
   - Tier 2 (E2E для нашего кластера): Интеграционные тесты в `tests/e2e/`, работающие с реальным S3 endpoint. Обязательное условие — изолированный бакет `test-jules-*` и строгий teardown (удаление бакета/объектов после тестов, чтобы не мусорить на VPS).
   - Четкие интерфейсы: классы, методы get/set/invalidate/cleanup, Pydantic-модели метаданных, обработка сетевых таймаутов.
4. Представь сформированный план мне на утверждение (Manual Gate) и жди моего «ок».
5. После утверждения создай GitHub Issue с планом для Jules в репозитории.
6. Когда Jules откроет PR:
   - Запусти субагента QA/Reviewer для прогона `tests/e2e/` против нашего Garage S3 (http://10.20.0.6:3900) во временном scratch-пространстве.
   - При ошибках — отправить репорт в PR через `gh pr comment`. При успехе — показать отчёт и diff для финальной приёмки.
